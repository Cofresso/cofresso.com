# Database

Cloud SQL Postgres 16, instance `cofresso-pg`, databases `cofresso` (production) and `cofresso_preview`.

## Connect locally

```bash
gcloud sql connect cofresso-pg --user=cofresso --database=cofresso --project cofresso-prod
# password: gcloud secrets versions access latest --secret db-password --project cofresso-prod
```

## Migrations

Generated by `pnpm db:generate` from `src/lib/db/schema`, applied by the `cofresso-migrate*` Cloud Run jobs before each deploy. Both jobs' args are `dist/db.mjs deploy` — the CLI's `deploy` subcommand migrates and then runs the idempotent seed in one process, so CI needs exactly one execution and no argument overrides. Run one manually:

```bash
gcloud run jobs execute cofresso-migrate --region us-central1 --project cofresso-prod --wait
```

The CLI (`scripts/db.ts`, bundled to `dist/db.mjs`) takes `migrate`, `seed`, `reset` or
`deploy`.

## Reset the preview database

`gcloud run jobs execute --args=...` is broken in gcloud 548.x (it sends an unknown
`priorityTier` field and fails client-side), so change the job's args with `jobs update`,
execute it, then put the args back:

```bash
gcloud run jobs update cofresso-migrate-preview --region us-central1 --project cofresso-prod \
  --args="dist/db.mjs,reset" --update-env-vars ALLOW_DB_RESET=true --quiet
gcloud run jobs execute cofresso-migrate-preview --region us-central1 --project cofresso-prod --wait
# Restore the defaults so the next preview deploy does not reset the database:
gcloud run jobs update cofresso-migrate-preview --region us-central1 --project cofresso-prod \
  --args="dist/db.mjs,deploy" --remove-env-vars ALLOW_DB_RESET --quiet
```

`reset` refuses to run unless `ALLOW_DB_RESET=true`, which is why it is not set on either
job by default. Never run `reset` against `cofresso-migrate`.

## Backups

Daily automated backups, 7 retained. Restore through the Cloud SQL console or `gcloud sql backups restore`.
